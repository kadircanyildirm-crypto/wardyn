wardyn · a kernel-level warden for AI coding agents

Inside the syscall:
where the agent is stopped

An AI agent asks the kernel to open your private key. Between the ask and the answer there are about four microseconds and six decisions. Wardyn lives in that gap — not as a wrapper the agent could see, but as 21 eBPF programs attached to the kernel's own hooks, and a second boundary drawn by Landlock. Press play and follow one syscall down. Then pick another.

§ 1one call, six decisions

What the kernel offers, and what wardyn makes of it

Nothing here is invented. Every mechanism below has been in mainline Linux for years; wardyn's whole idea is to stand on them rather than around the agent. Read the six cards, then click any box in the diagram — each one opens with what it is in the kernel and what wardyn does with it.

the kernel side six mechanisms
syscallsThe only door out of a process~450 entry points. Each takes up to six arguments and returns one integer — a descriptor, or a negative errno. Everything below the boundary runs at ring 0.

§ 3from rule to kernel key

What the kernel is actually given

A BPF hook cannot run a glob matcher. Every policy.yaml rule is reduced to a fixed-width key the kernel can look up in a hash map or an LPM trie — and the reduction can only ever go one of three ways. Wardyn tells you which, at startup and in --dry-run, because a rule whose key is broader than its text is the failure this project exists to refuse.

§ 4two boundaries, two mechanisms

A blocklist and an allowlist are different shapes

eBPF · tracepoints, BPF-LSM, cgroupName what is forbidden

files:
  - { match: "**/.env",        action: block }
  - { path:  "~/.ssh",         action: block, access: all }
network:
  - { cidr: "0.0.0.0/0",      action: block }
exec:
  - { match: "**/nc",          action: block }
  • Anything the policy forgot stays reachable. That is what a blocklist is.
  • Can say warn — flag without denying — and can be excepted from the TUI, once, for the rest of the run.
  • Sees addresses. The only half that can decide egress by CIDR, port and protocol, four LPM tiers deep.
  • Needs root to load. The agent has none, so it cannot touch the maps.

Landlock · ABI 1–7Name what is reachable

allow_paths:
  - { path: "/usr", rights: [read, exec] }
  - { path: "/etc", rights: [read] }
  - { path: ".",    rights: [read, write, exec] }
allow_ports: [443, 53]
  • Everything unlisted is unreachable — /home, another checkout, a mounted drive, the agent's own loader if you forget it.
  • No privilege needed. Applied in the child before exec, inherited by every descendant, impossible to undo — it holds even for a root agent.
  • By port only for TCP. Landlock has no notion of an address, which is exactly why it sits beside the eBPF hooks.
  • Reports to nobody. Wardyn's feed reconstructs its denials — and its end-of-run cross-check knows not to count them against the kernel's counters.
They compose. Containment removes everything outside; the block rules still deny specific objects inside what remains; egress stays decided by eBPF for hosts and by Landlock for ports. An agent confined to the project by allow_paths: still cannot read the project's own .env if a files: rule names it.
§ 5saying what happened

A tool that reports on a kernel has one job it cannot fail at

Most of wardyn's fixed bugs were the same bug: the tool saying something about itself that was not true. The feed vocabulary, the startup notices and the end-of-run cross-check exist so that the honest answer is always the one on screen.

okObserved, permitted. Streamed too — a log that only records violations cannot show what an agent actually did.
⚠ warnFlagged by policy, not denied. Either the rule said warn, or it is a block that observe mode never enforces.
⛔BLOCKDenied, and the kernel confirmed it with its own DENY_* event. A prediction never outranks the kernel's word.
block~The policy says block, but the kernel cannot enforce it — the LSM did not attach, the offsets were untrusted, or the glob does not reduce to a key. Flagged, and honest about why.
startuppolicy `/etc/shadow` (block) enforces on any file named `shadow` directly under a dir named `etc` — the kernel matches by name, so it will also deny paths the glob wouldn't. Write `{ path: "/etc/shadow", action: block }` to pin exactly that file.
startupthe policy file policy.yaml is writable by the agent (uid 1000) — it could rewrite the rules that constrain it before the next run.
startuppid namespace detected (self 461, kernel view 22794) — relying on in-kernel fork adoption; the feed shows init-ns pids
exitkernel denials — 15 file, 0 exec, 5 network · 15 of those matched by identity (dev,ino) — a rename or hard link would have defeated a name rule.
exitWARNING: 17227 event(s) were dropped by a full ring buffer — those actions have no feed row, no audit record and no receipt line.
exitWARNING: 26 denial(s) were reported to the agent but the kernel counted none — enforcement did NOT fire. Treat this run as observe-only. (the cross-check that cannot be fooled by a wrong struct offset)

§ 7what it does not do

Stated, so nobody discovers it the hard way

io_uring Submissions bypass the syscall tracepoints, so they are missing from the feed. The LSM hooks still fire on the actual open.
AF_UNIX & loopback delegation An agent that asks a local daemon to do its reading is not watched through the daemon.
Raw sockets SOCK_RAW / AF_PACKET skip the cgroup hooks — and need CAP_NET_RAW, which the dropped agent does not have.
The policy file's location ./policy.yaml is the default, and that directory is the agent's. Wardyn warns; it does not refuse.
Name rules and mv A match: glob is a name. Renaming defeats it — which is what path: identity rules are for.
One maintainer There is no second person with merge rights. GOVERNANCE.md says so before you depend on it.

The observer cannot deny

The tracepoint sees the call and reports it. The verdict is the LSM hook's, further down. The hook that decides is the hook that reports, so the feed can never claim a denial the kernel never made.

Names lose, inodes don't

A path: rule keys on (dev, ino) — the object itself. Rename it, hard-link it, move the directory: the inode is unchanged, and so is the verdict.

Losing the log is not losing the boundary

The verdict is decided inside the syscall. The report goes through a ring that can fill — and when it does, wardyn says so in numbers. A silent drop would be the real failure.
